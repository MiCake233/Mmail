# Mmail · Android

WebView shell for Mmail. The project bundles `web/` from the repository root as Android assets, so the interface, bilingual copy, login history, and themes are identical to the desktop and web builds.

## Status

| Capability | State |
| --- | --- |
| Provider entries, search, filters, favourites | Works (shared `web/`) |
| Recents and login history | Works (`localStorage`) |
| Chinese / English interface, light / dark theme | Works (follows the system) |
| External links open in the system browser | Works |
| Back button navigates the page | Works |
| Background mail alerts (IMAP + notification) | Not implemented |

The interface states that mail alerts require the desktop build. It does not simulate the feature.

## Build

Android Studio, or the Android SDK with JDK 17.

```bash
# Android Studio: File -> Open -> select this android/ directory, then Run
# Command line, with ANDROID_HOME set:
cd android
./gradlew assembleDebug        # output: app/build/outputs/apk/debug/
```

The Gradle wrapper jar is not committed; Android Studio adds it on first sync. On the command line, run `gradle wrapper` once if Gradle is installed.

## How the assets are wired

`app/build.gradle` adds the repository `web/` directory as an asset source:

```gradle
sourceSets {
    main {
        assets.srcDirs += ['../../web']
    }
}
```

`MainActivity` serves those assets through `WebViewAssetLoader` at
`https://appassets.androidplatform.net/assets/index.html`. This provides a stable origin for `localStorage` and avoids enabling `file://` access.

Consequence: interface changes are made once, in `web/`, and apply to every target.

Icons are generated by `npm run icons`, which writes `res/mipmap-*/ic_launcher.png` from `assets/icon-source.jpg`.

## Background alerts

The desktop build talks IMAP directly from Node. Android has no equivalent API, so alerts require native work:

1. A `WorkManager` periodic job (minimum interval 15 minutes) or a foreground service.
2. A native IMAP client: port the parsing logic from `electron/imap.js`, or adopt `jakarta.mail`.
3. A notification channel, with a tap action that opens the provider's webmail.
4. Credential storage in `EncryptedSharedPreferences` or the Android Keystore.
5. The `POST_NOTIFICATIONS` runtime permission on Android 13 and later.

Until then, the Android target remains an entry launcher with local history.
